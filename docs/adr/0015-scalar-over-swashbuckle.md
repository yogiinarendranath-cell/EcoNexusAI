# ADR-0015: Scalar over Swashbuckle for API Docs

**Status:** Accepted
**Date:** 2026-09-28
**Decision Makers:** CTO, Lead Engineer

---

## Context

The API ships OpenAPI documentation. Two libraries are commonly used in .NET:

1. **Swashbuckle.AspNetCore** — the historic standard. Generates OpenAPI 2.0 /
   3.0 and serves Swagger UI.
2. **Microsoft.AspNetCore.OpenApi** — the newer, in-box OpenAPI generator
   (introduced in .NET 9). Generates OpenAPI 3.1. Does not bundle a UI.

We initially used both at once — Swashbuckle for the UI and MS OpenAPI for the
spec — which duplicated config and caused confusion.

---

## Decision

Adopt **Microsoft.AspNetCore.OpenApi** as the sole spec generator, and
**Scalar.AspNetCore** for the interactive UI.

- Spec: `/openapi/v1.json` (OpenAPI 3.1, generated by MS OpenAPI).
- UI: `/scalar/v1` (modern, dark-mode, request/response examples).
- Swashbuckle is removed entirely (package, config, using directives).

---

## Consequences

**Positive:**
- One spec source, one config block.
- OpenAPI 3.1 (Swashbuckle primarily targets 3.0).
- Scalar UI is significantly nicer than Swagger UI — dark mode, cleaner
  request previews, code snippets in multiple languages.
- `Microsoft.AspNetCore.OpenApi` is first-party and evolves with .NET.

**Negative:**
- Old links to `/swagger` no longer work — a compatibility break for anyone
  who bookmarked them (acceptable at this stage).
- Scalar is a third-party package; if it becomes unmaintained we'd swap in
  another UI (Redoc, Stoplight, or the plain JSON spec).
- Scalar's UI is not customizable to the same degree as Swagger UI.

---

## Alternatives Considered

- **Keep Swashbuckle only** — fewer moving parts but older spec version and UI.
- **Keep both** — the pre-decision status quo; confusing and duplicated.
- **Microsoft.AspNetCore.OpenApi + Redoc** — Redoc is bundled with some
  Microsoft templates; Scalar is the modern default.
- **No UI, JSON only** — fastest but reduces developer experience.
